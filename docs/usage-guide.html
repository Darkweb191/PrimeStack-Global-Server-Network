Getting Started Setup & quickstart

PrimeStack is a modular monolith — one deployable process, clean module boundaries, designed to extract to microservices when needed. Every financial operation flows through the double-entry ledger.

⚠️
Prerequisites Node.js ≥ 24, Docker Desktop, and PostgreSQL 15+ are required. Redis is managed via docker-compose.

Quick Setup

  1. 1
    Start infrastructure

    Spin up PostgreSQL and Redis containers.

  2. 2
    Install dependencies

    Run npm install in the project root.

  3. 3
    Generate Prisma client

    Run npx prisma generate and npx prisma db push to apply the schema.

  4. 4
    Seed the database

    Run npx tsx prisma/seed.ts — creates admin user, demo merchant, and HMAC key.

  5. 5
    Start the server

    Run npm run dev — server listens on http://localhost:8081.

bash
# 1. Start PostgreSQL + Redis
docker compose up -d

# 2. Install deps
npm install

# 3. Apply schema
npx prisma generate
npx prisma db push

# 4. Seed (saves HMAC secret to stdout)
npx tsx prisma/seed.ts

# 5. Run dev server
npm run dev
# → Server running at http://localhost:8081

Authentication HMAC-SHA256 & JWT

PrimeStack uses two authentication mechanisms depending on the caller context.

🔑 HMAC-SHA256 — Merchant/API

Used by merchants and server integrations. Signs the request body with a shared secret key. Suitable for server-to-server calls.

🎫 JWT Bearer — Admin UI

Used by the admin dashboard and management endpoints. Short-lived access tokens obtained via the login endpoint.

HMAC Authentication

Each API call must include three headers. The signature covers the raw request body.

http
POST /transfers HTTP/1.1
X-Key-ID: psk_demo_key_001
X-Timestamp: 1700000000000
X-Signature: sha256=<HMAC-SHA256(secret, body)>
Content-Type: application/json

Generating the signature (Node.js)

typescript
import { createHmac } from 'node:crypto';

function signRequest(secret: string, body: string): string {
  return 'sha256=' + createHmac('sha256', secret)
    .update(body)
    .digest('hex');
}

const body = JSON.stringify({ amount: '100.00', currency: 'USD' });
const signature = signRequest(process.env.HMAC_SECRET, body);

JWT Authentication

Obtain a token via the admin login endpoint, then pass it as a Bearer token.

http
POST /admin/auth/login
Content-Type: application/json

{
  "email": "admin@primestack.io",
  "password": "Admin@2026"
}

→ Response:
{
  "success": true,
  "data": {
    "token": "eyJhbGci...",
    "expiresAt": "2026-01-02T00:00:00Z"
  }
}

→ Use in subsequent requests:
Authorization: Bearer eyJhbGci...

S2S Engine /s2s/* — ★ New Module

The Server-to-Server engine handles encrypted, signed transaction payloads between trusted parties. It supports payload encryption (AES-256-GCM) layered on top of HMAC authentication for high-security integrations.

🔒 Payload Encryption

AES-256-GCM encryption for sensitive transaction data. Each request uses a unique IV. Keys are rotated per session.

⚡ Low-Latency Processing

Optimized pipeline with Redis-backed session state. Typical round-trip under 50ms on co-located infrastructure.

🔄 Idempotent Replays

S2S transactions are fully idempotent. Safe to retry on network failure — no double-charges.

MethodPathAuthDescription
POST/s2s/sessionsHMACCreate S2S session
POST/s2s/transactionsHMAC + SessionSubmit S2S transaction
GET/s2s/transactions/:idHMACGet S2S transaction status
POST/s2s/sessions/:id/refreshHMACRefresh session key
DELETE/s2s/sessions/:idHMACTerminate session
GET/s2s/sessions/:id/statsHMACSession statistics

S2S Session Flow

typescript
// 1. Create a session
const session = await fetch('/s2s/sessions', {
  method: 'POST',
  headers: hmacHeaders(body),
  body: JSON.stringify({
    merchantId: 'MERCHANT-001',
    ttlSeconds: 3600
  })
});
// → { sessionId, encryptionKey, iv }

// 2. Encrypt payload with returned key
const encrypted = encryptAES256GCM(sessionKey, transactionPayload);

// 3. Submit transaction
await fetch('/s2s/transactions', {
  method: 'POST',
  headers: { ...hmacHeaders(encrypted), 'X-Session-ID': session.sessionId },
  body: encrypted
});

Ledger Module /ledger/*

The immutable double-entry journal. Every financial operation — transfer, settlement, fee, chargeback, reversal — creates a journal entry here. The ledger is the source of truth.

⚠️
Core Design Rule Every financial change must call LedgerService.postEntry(). Direct DB writes that bypass the ledger violate double-entry invariants and will break reconciliation.

Extending AppError

typescript
import { AppError } from '../../core/errors';

// ✅ Correct — use AppError
throw new AppError('INSUFFICIENT_FUNDS', 422);

// ❌ Wrong — never throw plain Error in services
throw new Error('not enough money');

// With i18n message key:
throw new AppError('INSUFFICIENT_FUNDS', 422, {
  messageKey: 'errors.INSUFFICIENT_FUNDS'
